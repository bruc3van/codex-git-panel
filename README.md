# Codex Git Panel

**在 Codex 工作流中，手动查看差异、暂存文件、提交版本和同步远端。**

中文 · [English](README.en.md)

Git Panel 是一个本地 Codex 插件。通过提示词或 Skill 让 Codex 在内置浏览器打开面板后，你可以直接点击操作 Git。适合检查 AI 修改、整理一次提交，也适合为笔记、文档和个人项目保留本地版本。

![Git Panel 浅色界面：已暂存文件、工作区差异和提交历史](docs/images/git-panel-light.png)

## 功能

| 场景 | 支持的操作 |
| --- | --- |
| 检查改动 | 区分已暂存与未暂存文件，查看带行号的统一差异，预览新文件 |
| 整理提交 | 按文件暂存、取消暂存，确认后放弃已跟踪文件的未暂存修改 |
| 保存版本 | 输入说明提交，支持 `Ctrl + Enter`，按仓库保留未发送的提交说明 |
| 回看历史 | 查看近期提交及其差异，区分当前提交和上游位置 |
| 切换分支 | 工作区干净时，切换到已有的本地分支 |
| 同步远端 | Fetch、仅快进 Pull、推送到已配置的上游，显示待拉取/待推送数量 |
| 本地版本管理 | 让 Codex 初始化文件夹后，在面板中查看、暂存和提交，无需 GitHub 账号或远端 |
| 使用习惯 | 浅色、深色、跟随系统；可调整列表宽度及历史区域高度；Windows 默认应用打开文件 |

## 让 Codex 安装插件

需要 **Node.js 20+、Git，以及支持插件的 Codex 客户端**。Windows 已完成运行验证，Linux 服务端测试已在 WSL Ubuntu 通过；macOS 尚未完成运行验证。面板目前以中文为主，部分 Git 操作使用英文标签。

将下面整段提示词复制到 Codex：

```text
请帮我安装并启用 https://github.com/bruc3van/codex-git-panel 插件。

1. 阅读仓库 README，检查本机 Node.js 20+、Git 和 Codex 插件能力。将仓库克隆到稳定的用户目录；如已安装，复用现有目录并保留本地修改。
2. 插件根目录是 plugins/git-panel。按当前 Codex 支持的本地插件/marketplace 机制完成安装和启用，保留其他插件配置，不要把整个仓库误当成插件根目录。
3. 验证插件已安装、启动脚本存在，并验证服务绑定指定仓库。安装过程不要暂存、提交、推送或初始化我的工作目录。
4. 安装完成后，引导我新建任务加载插件；如果客户端仍未识别插件，引导我保存工作、完全退出并重新打开 Codex，再新建任务，不要强制关闭客户端。
5. 告诉我如何通过自然语言提示词，或输入 / 或 $ 搜索并选择 git-panel Skill，在 Codex 右侧内置浏览器打开面板。若内置浏览器工具不可用，提供本地链接并说明限制。
```

安装后**新建任务**加载 Skill；若客户端没有识别到插件，请保存工作，完全退出并重新打开 Codex，再新建任务。

## 打开面板

### 1. 对 Codex 说一句话

```text
打开当前仓库的 Git 面板。
```

也可以指定目录：

```text
打开 <本地仓库路径> 的 Git 面板，我要手动检查并提交更改。
```

Skill 会启动服务，并优先通过 Codex 工具在内置浏览器中打开；客户端没有该工具时返回本地链接。打开面板本身不会执行提交或同步。

### 2. 斜杠菜单或 Skill 选择器

在对话输入框输入 `/`，继续搜索 `git-panel` 并选择已安装的 Skill，然后发送打开面板的请求；也可以输入 `$` 搜索并选择它。以客户端实际显示的名称为准，不需要输入 Skill 文件路径。若未出现，检查插件是否启用，并在重启后新建任务。参见 [Codex 斜杠指令说明](https://learn.chatgpt.com/docs/reference/slash-commands)。

这两种选择器均由 Codex 执行 Skill，并非绕过模型的系统快捷键。

## 为文件夹建立本地版本记录

初始化由 Codex 根据你的请求执行，完成后再在内置浏览器打开面板：

```text
请将 <文件夹路径> 初始化为本地 Git 仓库并打开 Git 面板，暂不创建远端，也不要自动提交。
```

初始化不会自动暂存、提交或添加远端；位于已有仓库中的目录使用所属仓库。首次提交需要本机配置 Git 用户名与邮箱。没有远端仍可使用本地功能，远端按钮会按仓库状态禁用。

## 提交与同步

1. 点击文件查看差异，使用 `+` / `−` 选择本次提交的文件。
2. 填写说明，点击 **Commit** 或在说明框按 `Ctrl + Enter`。
3. **已有暂存文件时，只提交暂存内容；没有暂存文件时，会暂存全部更改并提交。** 若只想提交部分文件，请先暂存它们。若自动暂存后提交失败，暂存内容会保留。
4. 工作区干净且有待推送提交时，主按钮切换为 **Push**，说明框内的 `Ctrl + Enter` 同样执行 Push；同步需要已有上游配置。Pull 仅允许快进，分叉、冲突和正在进行的合并/变基需要先在终端处理。

## 命令行启动

在克隆的本仓库目录中执行，将占位路径替换为实际仓库路径：

```sh
node plugins/git-panel/scripts/launch.mjs "<repository>"
```

命令启动或复用服务并输出本地 URL，不自动打开浏览器。通过 Skill 启动时，Codex 会使用该 URL 打开右侧内置浏览器。

## 常见问题

- **找不到 Skill：** 检查插件是否启用，新建任务；仍未出现时完全退出并重启 Codex。
- **面板没有打开：** 在终端运行 `launch.mjs` 查看错误，并确认 Node.js 和 Git 可用。内置浏览器工具不可用时，可手动打开返回的本地 URL。
- **文件无法用默认应用打开：** 面板内的文件打开功能目前仅支持 Windows，且不允许通过该入口执行脚本、程序或快捷方式。
- **认证、签名或 Git hook 出错：** 使用本机 Git 配置；需要交互的凭据或签名流程请先在终端完成。
- **升级与卸载：** 更新源码后让 Codex 重新安装插件，再新建任务；客户端未识别时重启。卸载使用 Codex 的插件管理功能。

当前不提供分块暂存、并排 diff、创建分支、冲突解决界面或 AI 提交说明生成。历史差异按第一父提交比较。

## 多项目与服务生命周期

不同仓库或 worktree 使用独立地址；同一工作区的多个面板共用文件和暂存区，操作会影响彼此。一个新版服务会阻止重叠的 Git 操作，但不会锁住外部编辑器或终端。

插件升级时仍复用正在运行的服务；关闭相关页面并等待空闲退出后，再打开即可加载新版。升级前已运行的旧服务没有自动回收或跨版本复用能力，需要确认没有操作后手动停止；不要在旧、新服务中同时操作同一个仓库。macOS/Linux 服务异常退出后，启动器会探测并自动清理当前用户的无监听 socket。若恢复过程本身被强制终止，启动错误会指出 `.recovery` 锁路径；确认所有相关启动进程已退出后再删除该锁。升级旧版 Unix 服务前，请先停止旧服务，避免运行目录迁移后出现两个实例。

## 本地运行与开发

服务只监听 `127.0.0.1`，每个实例绑定一个工作区，以随机会话凭据及 Host/Origin 校验保护接口。启动 URL 含会话凭据，请勿分享。新版启动器按工作区复用服务，不同插件安装路径也会复用同一实例；并发首次启动由进程级单实例入口保护。可见面板每 5 秒同步状态和当前差异，后台页面发送轻量保活请求。最后一次页面请求后空闲约 10 分钟，且没有 Git 操作或请求执行时，服务自动退出。浏览器长时间冻结后可能需要通过 Skill 重新打开。Windows 运行记录位于 `%LOCALAPPDATA%/CodexGitPanel`（未设置时使用用户主目录）；Unix 使用 `$XDG_RUNTIME_DIR/CodexGitPanel`，未设置时使用 `~/.local/share/CodexGitPanel`，目录权限为 0700，新记录权限为 0600；可按记录中的 PID 停止对应服务。

```sh
npm start
npm test
```

运行时只依赖 Node.js 与 Git。测试使用临时仓库覆盖 Git 操作、HTTP 边界、并发启动、跨路径复用及空闲回收，不对用户仓库提交或推送。源代码位于 `plugins/git-panel`，测试位于 `tests`。

文件列表每组最多渲染 500 项并显示提示，自动暂存提交仍包含完整文件列表。超过 2000 行或 250KB 的差异使用纯文本预览；Git 输出超过 4MB 时提示在终端处理。宽度不超过 600px 时，预览占满内容区，关闭预览即可返回列表。

Unix socket 位于 `/tmp/codex-gp-<uid>` 私有目录，以避免系统 socket 路径长度限制。
