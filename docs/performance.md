# 性能优化验证（2026-09-10）

针对重复 Git 查询、并发读请求叠加和重复 DOM 构建做了调整：

- 同一服务中的并发状态查询共享正在执行的查询，完成后释放引用，不缓存完成的状态。写操作前后使旧查询失效，写操作自己重新读取状态并校验暂存快照。
- 文件 diff 只读取文件状态，不再额外查询分支、历史、上游、索引快照等全部状态。
- Git 命令队列最多同时执行 2 项，最多等待 32 项，超限明确报错；取消等待任务会移除队列项。
- 切换 / 关闭预览时取消旧请求；HTTP 连接断开会中止对应 diff 的 Git 命令或文件读取。写操作不会因浏览器断开而取消。
- 文件列表和 diff 内容不变时保留 DOM；历史提交预览不再每轮重取。工作区 diff 仍定期读取，确保同样显示 M 状态的后续内容变化能被发现。
- 输入提交说明只更新主按钮，不再遍历所有文件操作按钮。

## 本机前后对比

Windows、Node v24.19.0，使用相同 execFile 计数包装与临时仓库。耗时随系统负载波动，命令数量更适合作为稳定的对比指标。

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 小仓库状态 + 已跟踪文件 diff | 每轮 17 条 Git 命令 | 每轮 10 条，减少约 41% |
| 上述场景 3 批各 10 轮平均耗时 | 869 / 878 / 855ms | 415 / 427 / 514ms |
| 2001 个已跟踪文件，10 轮平均耗时 | 969ms | 454ms |
| 8 个并发状态查询的总 Git 命令数 | 64 | 8 |
| 上述并发查询的实测 Git 并行峰值 | 8 | 1 |
| 服务端反复查询后 GC 堆大小 | 约 7.8–8.0MB | 约 7.8–7.9MB |

浏览器连续打开 / 关闭预览 10、20、30、40 次后，GC 堆为 2.469、2.538、2.550、2.571MB；每轮 DOM 节点 308、事件监听器 76，未持续累积。数字包含浏览器测试工具影响，不能直接等同于 Codex 总内存。

浏览器同时验证：跨轮询保留未变化 DOM，输入说明不重建文件列表，外部修改内容但 Git 状态仍为 M 时更新 diff，关闭预览取消请求且不显示错误，Ctrl+Enter 提交与 Push。测试 Push 仅指向临时本地裸仓库。

新增回归覆盖队列容量、等待取消、执行失败后恢复、状态查询合并、外部修改可见、stale commit 拒绝、开始前及执行中取消 diff。Windows 与 WSL Ubuntu 均执行验证；不代表长期运行或 macOS 真机已完成性能测试。
